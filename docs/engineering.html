Case study

Engineering

A generative MIDI effect that owns timing-safe generation across multiple algorithmic engines, wrapped for real hosts, with decisions and evidence kept on disk.

Problem

Problem / thesis

MIDI FX plugins fail employers’ diligence when the story stops at “clever UI.” The hard part is a coherent system: engines that generate musical events, a processor that bridges parameters safely, format wrappers that load in real DAWs, and records that show what was verified versus deferred.

Generative MIDI is that full stack for a macOS MIDI effect — development status v0.8.0 per STATUS.md — built so architecture and proof are drillable without a scavenger hunt.

Architecture

Architecture

Layers from host boundary inward: format clients, PluginProcessor (APVTS + lifecycle), core engines and MIDI scheduling, then editor/UI.

  • Core engines — Euclidean, Algorithmic (Markov, L-System, Cellular, Probabilistic), Stochastic (Brownian, Perlin, Drunk Walk, Lorenz); Polyrhythm retained in core.
  • MIDI path — MIDIGenerator, clock/event scheduling, gate and ratchet controllers.
  • PluginProcessor — parameters (31), generator dispatch, host callbacks.
  • Formats — AU, VST3, Standalone verified locally historically; AUv3 configured in CMake with iOS docs (not store-ready). CI: .github/workflows/ci.yml.
  • Editor — LookAndFeel / steampunk craft; bitmap UI path documented; Polyrhythm not in APVTS or dropdown; 10 factory presets.

Hard parts

Where the work concentrates

  • Realtime / scheduling

    Note generation must respect host block timing. Gate length and ratchet features are described in STATUS with sample-accurate intent. Engine behavior is covered by Catch2 / ctest in CI; host timing still relies on historical format builds and manual checks — not a published latency bench suite.

  • Parameter bridging

    APVTS choices drive engines and UI. The live generator choice list matches the editor: nine generators (Euclidean + 4 algorithmic + 4 stochastic). Polyrhythm remains in core sources only — deferred from APVTS and the dropdown (no UI/param mismatch claim).

  • Bypass / lifecycle

    JUCE plugin client lifecycle (prepare, process, editor attach) plus COPY_PLUGIN_AFTER_BUILD install paths. Host integration is evidenced by build artifacts, CI, and developer build docs, not by claiming every DAW certified.

  • Measurement contracts

    On-disk contracts are STATUS.md, BUILD_VERIFICATION.md, CHANGELOG, and CI (.github/workflows/ci.yml + Catch2 / ctest) — not invented coverage percentages. Prefer “build passed / tests ran / feature listed” over marketing metrics.

Decisions

Selected design-decision highlights

  • Procedural LookAndFeel vs bitmap path Victorian steampunk craft started as custom drawing; bitmap UI infrastructure and Synaptik asset specs document the next craft layer without claiming finished product polish.
  • SynaptikUIToolkit as git submodule Shared UI toolkit lives in art/ as a submodule; build verification records that formats still built after the migration.
  • Modulation system archived Incomplete modulation v1 moved under archive/ rather than left half-wired in the editor — honesty over feature theater.
  • Polyrhythm deferred from UI Engine sources retained for a future branch; removed from APVTS and the editor dropdown. Live surface is nine generators — no fake “still in params” mismatch claim.

Roadmap

What’s next

No App Store timeline is implied. See STATUS.md and ENHANCEMENTS.md for the longer backlog.
